# Yardi Connector — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md`. Целевой пользователь: Property/Asset
Manager крупного портфеля недвижимости на Yardi (industry-стандарт enterprise-уровня).

## 1. Credential type
WSDL URL (SOAP-based, не REST) + вероятно credentials далее в схеме + выбор конкретного
интерфейса (`interface`: common_data/billing/etc — Yardi предоставляет РАЗНЫЕ WSDL-
интерфейсы для разных функциональных областей, каждый требует ОТДЕЛЬНОГО подключения).

## 2. Идеальный флоу
1. **Первое открытие** — `Empty` с ЧЕСТНЫМ объяснением: "Yardi предоставляет несколько
   отдельных веб-сервисов (Common Data, Billing, Vendor Invoicing и др.) — подключите
   те, что вам нужны, каждый отдельно" — это ключевое архитектурное отличие Yardi от
   типового single-endpoint API, должно быть явным с первого экрана, а не открываться
   постепенно через ошибки "функция недоступна".
2. **Форма для каждого интерфейса** — interface select + wsdl_url (получаемый от
   Yardi-администратора клиента, обычно на *.yardiasp*.com).
3. **После успеха хотя бы одного интерфейса** — сводка по портфелю (occupancy rate,
   просрочки, заявки на обслуживание) — доступный набор функций явно ограничен тем,
   какие интерфейсы подключены (баннер "подключите Billing interface, чтобы видеть
   платежи" вместо скрытого отсутствия функции).
4. **Ошибка "WSDL fetch failed"** — конкретное сообщение — часто из-за неверного
   client-специфичного поддомена в URL.
